    Cas d’utilisation

    Le domaine de confiance d’IPS Pilgrimage porte sur les principaux processus métier qui font partie de la prestation de soins aux pèlerins pendant un pèlerinage.

    Les scénarios d’utilisation et les principaux processus métier sont décrits dans ce document de spécification aux liens ci-dessous :

    • Scénarios d’utilisation
    • Processus métier

    Normes techniques

    Les spécifications techniques sont consignées dans ce guide d’implémentation (IG) FHIR. Veuillez consulter la page des transactions pour connaître les spécifications détaillées des transactions définies par cet IG.

    Politique

    Ce domaine de confiance permet un échange de données par l’intermédiaire du pèlerin, sur la base du consentement du pèlerin. Les consentements sont consignés dans le CodeSystem IPS.HAJJ.CONSENT, et chaque consentement de pèlerinage figurant dans l’IPS d’un pèlerin nomme l’un d’eux dans Consent.policyRule.

    Conditions d’utilisation

    Le ValueSet IPS.HAJJ.CONSENT constitue les conditions d’utilisation de ce domaine de confiance : les politiques en vertu desquelles un participant peut déclarer agir. Il est consigné dans le domaine de confiance IPS-PILGRIMAGE du GDHCN Trust IG. Le cadre administratif et opérationnel 1.2 du GDHCN ne comporte pas encore d’annexe pour ce domaine de confiance ; cette consignation est donc rédigée à partir de cet IG.

    Consentement explicite et consentement implicite

    Ce guide suit le modèle de consentement du guide GDHCN Trust Network: Personal Health Wallet, qui repose sur IHE Privacy Consent on FHIR (PCF) 1.1.0 :

    • Consentement explicite. Le pèlerin donne son accord par un acte qui lui est propre : dans son portefeuille, ou auprès du conseiller, qui l’enregistre. Chaque consentement de pèlerinage est un consentement explicite, une adhésion volontaire (opt-in) : son Consent.category comprend le code OPTIN de HL7 v3 ActConsentDirective. Il indique son code IPS.HAJJ.CONSENT et la version du système de codes dans Consent.policyRule, et son source[x] en constitue la preuve : le texte de consentement présenté au pèlerin, accompagné de l’acte consigné. Le processus L du guide Personal Health Wallet (« Record Explicit Consent ») en décrit les étapes. Le consentement verbal et le consentement dans le portefeuille décrits dans les processus métier de ce guide sont tous deux des consentements explicites.
    • Consentement implicite. Le pèlerin ne fait rien, et la politique par défaut du Domaine de confiance s’applique (HL7 ActConsentDirective IMPLIED). Ce Domaine de confiance fonctionne par adhésion volontaire (opt-in) : sa valeur par défaut est la politique implicite IHE PCF Policy-deny. Sans consentement de pèlerinage, l’IPS n’est pas partagé.

    Les directives de consentement accompagnent le document. L’IPS du pèlerin (HajjIPS) porte les consentements de pèlerinage sous lesquels il est partagé, sous forme d’entrées de consentement, et les énumère dans sa section Directives anticipées (Advance Directives). Le processus M du guide Personal Health Wallet (« Add Consent Directives to a Shared or Issued Document ») en décrit les étapes. La copie contenue dans l’IPS sert de preuve au destinataire. La HIE d’origine applique la copie conservée dans son propre Consent Registry, car un IPS signé ne peut pas faire apparaître un retrait ultérieur.

    Nommer le consentement en vertu duquel agit un VHL Receiver

    Dans le cadre de l’option Verifiable Credential d’IHE ITI VHL (ITI-YY5), un VHL Receiver récupère le manifeste avec une attestation qu’il émet lui-même. Il peut nommer la politique de consentement en vertu de laquelle il agit dans le termsOfUse W3C VC 2.0 de cette attestation, avec une entrée Trust Domain policy par politique :

    {
  "@context": ["https://www.w3.org/ns/credentials/v2"],
  "type": ["VerifiableCredential", "VHLManifestCredential"],
  "issuer": "did:web:vhl-receiver.example.org",
  "validFrom": "2026-06-01T10:00:00Z",
  "validUntil": "2026-06-01T10:05:00Z",
  "credentialSubject": {
    "id": "https://vhl-sharer.example.org/List?_id=abc123def456",
    "manifest": { "url": "https://vhl-sharer.example.org/List?_id=abc123def456", "flag": "LP" },
    "recipient": "Ministry of Health, Taifafeki (fictional): pilgrimage facility"
  },
  "termsOfUse": [{
    "type": "http://smart.who.int/trust/StructureDefinition/TrustDomainPolicy",
    "id": "http://smart.who.int/ips-pilgrimage/CodeSystem/IPS.HAJJ.CONSENT#CONSENT-XXR"
  }],
  "proof": { "type": "DataIntegrityProof", "cryptosuite": "ecdsa-rdfc-2019", "proofPurpose": "assertionMethod", "verificationMethod": "did:web:vhl-receiver.example.org#key-1", "proofValue": "z…" }
}

    Le VHL Sharer ensuite :

    1. vérifie que chaque politique nommée figure dans ce ValueSet ;
    2. la confronte au Consent.policyRule des consentements de pèlerinage du pèlerin (système et code) ;
    3. décide comme le décrit le processus I de GDHCN Trust Network: Personal Health Wallet.

    Nommer une politique ne fait que restreindre les consentements applicables, et ne prévaut jamais sur une interdiction. Une attestation sans termsOfUse est évaluée au regard de l’ensemble des consentements applicables du pèlerin.
