    消息语义：请求
    • 检索 VHL 文件夹文档请求的消息语义应当是一个按 SMART Health Link 清单请求规定的 POST 请求，并在请求正文中附带所提供的通行码。
    消息语义：响应
    • 消息语义应当遵循 ITI-67 查找文档引用（Find Document References）响应消息的修改版本，对于成功的查询，返回一个 FHIR bundle，其中包含该朝圣者 VHL 文件夹中所有可用的 documentReference。对 ITI-67 事务的修改在于：来源国 HIE 应当遵从值为 List:item 的 _include 搜索参数，因为 VHL 载荷中生成的 URL 格式为：

      {host}/List?_id={folder_id}&_include=List:item”

    东道国电子病历（EMR）的身份认证

    检索 VHL 文件夹文档请求对应于 IHE 可验证健康链接（VHL）检索清单事务 [ITI-YY5]。此处引用的 VHL 版本为 1.0.0-comment，这是一个公开征求意见的投票版本，而非正式版或试行实施版出版物；其文本和章节编号可能会变化。下文引用的章节读自 IHE/ITI.VHL 源代码（提交 48201473），而非已发布的投票版页面。

    VHL [ITI-YY5] 规定了 VHL 接收方（此处为东道国 EMR）向 VHL 共享方（此处为来源国 HIE）进行身份认证的三种选项：

    • HTTP 消息签名（RFC 9421），ITI-YY5 §2:3.YY5.4.1.3；
    • OAuth with SSRAA 选项，使用 HL7 可扩展注册、身份认证与授权安全（SSRAA）实施指南，即 UDAP 的 HL7 FHIR 规范，ITI-YY5 §2:3.YY5.4.1.4；
    • 可验证凭证选项，ITI-YY5 §2:3.YY5.4.1.5。

    本指南目前展示的是东道国 EMR 使用 mTLS 节点认证（[ITI-19]）向来源国 HIE 进行身份认证（参见非计划诊疗接诊的时序图）。mTLS 节点认证并不属于 VHL 的三种身份认证选项之一。VHL 仍然要求安全传输：ITI-YY5 §2:3.YY5.5.1 要求在传输安全方面符合 IHE ATNA 规范，而 VHL 第 1 卷 §1:XX.3 要求 VHL 接收方和 VHL 共享方与 ATNA 安全节点（Secure Node）或安全应用（Secure Application）组合在一起。因此仍然需要 TLS 通道，但仅靠它本身并不能满足任何一种 VHL 身份认证选项。

    建议东道国 EMR 使用“OAuth with SSRAA 选项”进行身份认证。与当前的 mTLS 方式一样，它基于 X.509 证书：东道国 EMR 的证书链接到 ips-pilgrimage 信任域中所接受的信任锚，因此来源国 HIE 依据该信任来识别接收方，而无需查找单独的协议。在该选项下，SSRAA 的发现和注册须在请求访问令牌之前完成（ITI-YY5 §2:3.YY5.4.1.4）。东道国 EMR 的证书或密钥如何在 ips-pilgrimage 信任域中发布，本指南尚未作出规定。
