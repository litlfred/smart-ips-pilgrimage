    本信任域支持由朝圣者居中、基于朝圣者同意的数据交换。这些同意记录在 IPS.HAJJ.CONSENT CodeSystem 中，朝圣者 IPS 中的每条朝圣同意都在 Consent.policyRule 中指名其中之一。

    使用条款

    IPS.HAJJ.CONSENT ValueSet 是本信任域的使用条款：即参与方可以声明其所依据的策略。它记录在 GDHCN Trust IG 中的 IPS-PILGRIMAGE 信任域上。GDHCN 行政和运营框架 1.2 尚无针对本信任域的附件，因此该记录根据本 IG 起草。

    明示同意与默示同意

    本指南遵循 GDHCN Trust Network: Personal Health Wallet 指南的同意模型，该模型基于 IHE Privacy Consent on FHIR（PCF）1.1.0：

    • 明示同意。朝圣者以其本人的行为表示同意：在其钱包上表示，或向咨询师表示并由咨询师记录。每一项朝圣同意都是明示同意，即选择加入（opt-in）：其 Consent.category 包含 HL7 v3 ActConsentDirective 代码 OPTIN。它在 Consent.policyRule 中注明其 IPS.HAJJ.CONSENT 代码及代码系统版本，其 source[x] 即为证据：向朝圣者展示的同意文本，以及其已记录的行为。Personal Health Wallet 指南的流程 L（“Record Explicit Consent”，记录明示同意）描述了相关步骤。本指南业务流程中的口头同意和钱包上的同意均为明示同意。
    • 默示同意。朝圣者不采取任何行为，适用信任域的默认政策（HL7 ActConsentDirective IMPLIED）。本信任域采用选择加入（opt-in）：其默认政策为 IHE PCF 隐含政策 Policy-deny。若无朝圣同意，则不共享 IPS。

    同意指令随文档一同流转。朝圣者的 IPS（HajjIPS）以同意条目的形式携带其据以共享的朝圣同意，并在其预先指示（Advance Directives）部分列出这些同意。Personal Health Wallet 指南的流程 M（“Add Consent Directives to a Shared or Issued Document”，向共享或签发的文档添加同意指令）描述了相关步骤。IPS 中的副本是供接收方使用的证据。来源国 HIE 执行的是其自身同意登记库（Consent Registry）中保存的副本，因为已签名的 IPS 无法反映之后的撤回。

    指名 VHL 接收方所依据的同意

    根据 IHE ITI VHL（ITI-YY5）的可验证凭证选项（Verifiable Credential Option），VHL 接收方使用其自行签发的凭证检索清单。它可以在该凭证的 W3C VC 2.0 termsOfUse 中指名其所依据的同意策略，每项策略一条 信任域策略条目：

    {
  "@context": ["https://www.w3.org/ns/credentials/v2"],
  "type": ["VerifiableCredential", "VHLManifestCredential"],
  "issuer": "did:web:vhl-receiver.example.org",
  "validFrom": "2026-06-01T10:00:00Z",
  "validUntil": "2026-06-01T10:05:00Z",
  "credentialSubject": {
    "id": "https://vhl-sharer.example.org/List?_id=abc123def456",
    "manifest": { "url": "https://vhl-sharer.example.org/List?_id=abc123def456", "flag": "LP" },
    "recipient": "Ministry of Health, Taifafeki (fictional): pilgrimage facility"
  },
  "termsOfUse": [{
    "type": "http://smart.who.int/trust/StructureDefinition/TrustDomainPolicy",
    "id": "http://smart.who.int/ips-pilgrimage/CodeSystem/IPS.HAJJ.CONSENT#CONSENT-XXR"
  }],
  "proof": { "type": "DataIntegrityProof", "cryptosuite": "ecdsa-rdfc-2019", "proofPurpose": "assertionMethod", "verificationMethod": "did:web:vhl-receiver.example.org#key-1", "proofValue": "z…" }
}

    随后 VHL 共享方：

    1. 检查每项指名的策略是否在该 ValueSet 中；
    2. 将其与朝圣者各项朝圣同意的 Consent.policyRule（system 和 code）进行匹配；
    3. 按照 GDHCN Trust Network: Personal Health Wallet 流程 I 所述作出决定。

    指名某项策略只会缩小适用的同意范围，绝不会推翻禁止性规定。没有 termsOfUse 的凭证将依据朝圣者所有适用的同意作出决定。
