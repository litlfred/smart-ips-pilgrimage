    Пользовательские сценарии носят исключительно иллюстративный характер и призваны дать представление о типичном рабочем процессе.

    Как интерпретировать пользовательские сценарии

    Пользовательские сценарии могут быть полезными инструментами не только для лучшего понимания контекста, в котором будет работать цифровой инструмент, но и для получения представления о том, какие ключевые элементы данных необходимо записывать и учитывать в базе данных. Кроме того, контекст работы инструмента, раскрываемый пользовательскими сценариями, даёт представление о некоторых функциональных и нефункциональных требованиях, которым также должна отвечать система.

    В качестве примеров сценарии определяют: ключевые элементы данных, которые необходимо записывать и/или рассчитывать; логику поддержки принятия решений, которая может быть автоматизирована в системе; ключевые функциональные и нефункциональные требования, которые следует включить в систему, а также особенности, касающиеся подростков, которые следует учитывать.

    Публикация национальных открытых ключей для проверки

    Сервисы

    • Национальная HIE
    • GDHCN ВОЗ

    Описано в структуре SMART Trust GDHCN, согласно которой Участник GDHCN предоставляет Шлюзу сети доверия (TNG) GDHCN ВОЗ открытые ключи, которые могут использоваться для подписания медицинских документов, в частности Международной сводки о пациенте (IPS). Домен доверия, который будет использоваться для этого набора сценариев, — ips-pilgrimage

    Этот процесс является как предварительным условием для пользовательских сценариев 3.0, 4.0 и 5.0, так и регулярным процессом, выполняемым всякий раз при обновлении соответствующего ключевого материала шифрования.

    Публикация национальных терминологий

    Этот процесс предназначен для обмена национальными системами кодирования и наборами значений, которые используются в профиле IPS национальной HIE. По возможности следует использовать стандартизированные системы кодирования, однако признаётся, что национальные системы кодирования могут быть необходимы, в частности для кодирования терминологий лекарственных препаратов. Основная цель, по крайней мере на первых этапах обмена терминологиями, — не семантическая совместимость между национальной HIE и EMR принимающей страны, а поддержка медицинского работника принимающей страны при просмотре IPS.

    Эти терминологии следует передавать из национальной HIE в Терминологическую службу ВОЗ.

    • Профиль IHE Sharing Value Sets and Concept Maps (SVCM) (рекомендуется)
    • Обмен табличными данными

    После передачи в Терминологическую службу ВОЗ эти терминологии следует сделать доступными для получения из EMR принимающей страны посредством профиля IHE SCVM.

    Этот процесс является как предварительным условием для пользовательских сценариев 3.0, 4.0 и 5.0, так и регулярным процессом, выполняемым всякий раз при обновлении соответствующих терминологий.

    Выпуск медицинского документа в стране происхождения

    Это сценарий «этапа 1», в котором страна происхождения проводит оценку состояния здоровья паломника, получает согласие правомочных паломников и выдаёт QR-коды (Smart Health Link), содержащие их сводку о пациенте в виде IPS. QR-код может быть выдан в национальном медицинском кошельке или в виде напечатанного QR-кода.

    Клинический приём при незапланированной медицинской помощи

    Это сценарий «этапа 1», в котором паломнику в принимающей стране необходимо обратиться за помощью к медицинскому работнику принимающей страны. Паломник выступает посредником в обмене, показывая QR-код, выданный страной его происхождения. EMR принимающей страны использует QR-код для доступа к национальной IHE с целью получения сводки о пациенте (IPS).

    Клинический приём с экстренным доступом («разбить стекло»)

    Это сценарий «этапа 2», в котором паломник в принимающей стране находится без сознания и должен получить экстренную медицинскую помощь. Медицинский работник принимающей страны получает доступ к сводке о пациенте по регистрационному номеру паломника. До этого случая оказания экстренной помощи паломник должен был зарегистрировать своё согласие на предоставление доступа к своей записи либо через приложение национального медицинского кошелька, либо через национальный орган по делам паломничества.
