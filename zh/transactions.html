    以下是为 ips-pilgrimage 定义的事务

    记录来自钱包的同意 - 请求

    记录同意请求事件事务由来源国卫生解决方案向来源国 HIE 发起。该事务应当遵循 IHE PCF 记录同意（ITI-108）事务。来源国健康钱包承担同意记录（Consent Record）参与者角色，来源国 HIE 承担同意登记系统（Consent Registry）参与者角色。

    触发事件

    • 数字健康钱包已记录一条新的同意指令。

      消息语义

      消息语义：请求

    • 记录同意请求的消息语义使用以 PUT 或 POST http 请求发送的 FHIR Consent 资源。

    • 更多详情见https://profiles.ihe.net/ITI/PCF/ITI-108.html。

    • 具体而言，
      • 访问同意 - 创建（ITI-108）
      • 访问同意 - 更新（ITI-108）
    消息语义：响应
    • 参见 ITI 108 的创建和更新章节。创建/更新交互的成功或失败由 http 响应码表示（例如 400、200 等）。

      预期操作

    • 同意被存储在同意登记系统中。有关同意登记系统（Consent Registry）参与者的能力声明，请参见此处

    签发 VHL - 请求

    签发 VHL 请求事件事务由来源国健康钱包向来源国 HIE 发起。

    触发事件

    • 当数字健康钱包已记录一份包含披露和时限设置的隐私配置表单时，即启动签发 VHL 请求事务。

      消息语义

      消息语义：请求
    • 签发 VHL 请求的消息语义应当包含构建 SMART Health Link 载荷所需的参数，具体为
      • 通行码标志
      • 过期时间
    消息语义：响应
    • 签发 VHL 请求的响应应当包含一个通过 QR 码图像承载的序列化 CWT，具体如“预期操作”一节所规定。

      预期操作

      以下是来源国 HIE 收到隐私配置后的预期操作：

    • 来源国 HIE 为朝圣者创建一个文件夹，其中包括朝圣者的
      • FHIR 或 PDF 格式（或两者兼有）的 IPS 文档
      • 已签名的 IPS 文档，即文件夹中所含每个文档对应的 DSG jws JSON 对象
    • 应当（shall）遵循SHL 规范，按以下步骤创建 SMART Health Link，然后将其封装在HCERT 结构中，并以CWT 结构共享：
      • 按以下语法建立一个指向朝圣者文件夹内文档引用的位置：”{host}/List?_id={folder_id}&_include=List:item”，其中 ‘folder_id’ 是该朝圣者健康文档文件夹的唯一 ID。它应当（shall）用作 VHL 载荷中的健康链接 URL
      • 构造SHLink 载荷
        • 最小化
        • Base64url 编码
        • 加上前缀 shlink:/
      • 构建包含上一步所生成 SHL 的 HCERT
      • 构建包含 HCERT 的 COSE 载荷，并使用 Kid 对应的私钥签名
      • 使用头部、载荷和签名构建 CWT
      • 序列化 CWT 并使用 Base64 编码
      • 生成 QR 码

    检索 VHL 文件夹文档 - 请求

    检索 VHL 文件夹文档请求事件事务由东道国电子病历（EMR）向来源国 HIE 发起。

    触发事件

    • 当东道国 EMR 从扫描的 QR 码中提取出 VHL 载荷，且解密后的 CWT 得到一个内含该 VHL 载荷的 HCERT 载荷时，即发起检索 VHL 文件夹文档请求事务。

      消息语义

      消息语义：请求
    • 检索 VHL 文件夹文档请求的消息语义应当是一个按 SMART Health Link 清单请求规定的 POST 请求，并在请求正文中附带所提供的通行码。
    消息语义：响应
    • 消息语义应当遵循 ITI-67 查找文档引用（Find Document References）响应消息的修改版本，对于成功的查询，返回一个 FHIR bundle，其中包含该朝圣者 VHL 文件夹中所有可用的 documentReference。对 ITI-67 事务的修改在于：来源国 HIE 应当遵从值为 List:item 的 _include 搜索参数，因为 VHL 载荷中生成的 URL 格式为：

      {host}/List?_id={folder_id}&_include=List:item”

    东道国电子病历（EMR）的身份认证

    检索 VHL 文件夹文档请求对应于 IHE 可验证健康链接（VHL）检索清单事务 [ITI-YY5]。此处引用的 VHL 版本为 1.0.0-comment，这是一个公开征求意见的投票版本，而非正式版或试行实施版出版物；其文本和章节编号可能会变化。下文引用的章节读自 IHE/ITI.VHL 源代码（提交 48201473），而非已发布的投票版页面。

    VHL [ITI-YY5] 规定了 VHL 接收方（此处为东道国 EMR）向 VHL 共享方（此处为来源国 HIE）进行身份认证的三种选项：

    • HTTP 消息签名（RFC 9421），ITI-YY5 §2:3.YY5.4.1.3；
    • OAuth with SSRAA 选项，使用 HL7 可扩展注册、身份认证与授权安全（SSRAA）实施指南，即 UDAP 的 HL7 FHIR 规范，ITI-YY5 §2:3.YY5.4.1.4；
    • 可验证凭证选项，ITI-YY5 §2:3.YY5.4.1.5。

    本指南目前展示的是东道国 EMR 使用 mTLS 节点认证（[ITI-19]）向来源国 HIE 进行身份认证（参见非计划诊疗接诊的时序图）。mTLS 节点认证并不属于 VHL 的三种身份认证选项之一。VHL 仍然要求安全传输：ITI-YY5 §2:3.YY5.5.1 要求在传输安全方面符合 IHE ATNA 规范，而 VHL 第 1 卷 §1:XX.3 要求 VHL 接收方和 VHL 共享方与 ATNA 安全节点（Secure Node）或安全应用（Secure Application）组合在一起。因此仍然需要 TLS 通道，但仅靠它本身并不能满足任何一种 VHL 身份认证选项。

    建议东道国 EMR 使用“OAuth with SSRAA 选项”进行身份认证。与当前的 mTLS 方式一样，它基于 X.509 证书：东道国 EMR 的证书链接到 ips-pilgrimage 信任域中所接受的信任锚，因此来源国 HIE 依据该信任来识别接收方，而无需查找单独的协议。在该选项下，SSRAA 的发现和注册须在请求访问令牌之前完成（ITI-YY5 §2:3.YY5.4.1.4）。东道国 EMR 的证书或密钥如何在 ips-pilgrimage 信任域中发布，本指南尚未作出规定。

    预期操作

    • 接收方 OCHIE 检查 VHL 请求是否有效，并以 FHIR bundle JSON 形式返回 documentReference。
    • 接收方 OCHIE 充当 VHL 文档响应方（VHL Document Responder），必须符合 VHL Document Responder 的能力声明
    对请求作出决定：朝圣者的同意即为策略

    朝圣没有需要另行查找的数据共享协议。朝圣者的两条 HajjConsent 资源即为策略，每一条都约束其所指名的一方：

    • 来源方释放同意（例如 CONSENT-MYS，或本指南示例中虚构的 CONSENT-XXK）允许来源国 HIE 将 IPS 释放给 Consent.provision.actor 中指名的接收方（角色 IRCP，信息接收方），用于 Consent.provision.purpose 中的目的（TREAT），期限为 Consent.provision.period。来源国 HIE 依据其自身同意登记系统（Consent Registry）中的记录（由记录同意事务 [ITI-108] 记录）执行该同意，而非依据 IPS 中携带的副本。IPS 中的副本在签发 IPS 时签名，因此无法反映之后的撤回。
    • 东道国使用同意（CONSENT-KSA，或本指南示例中虚构的 CONSENT-XXR）约束东道国卫生部在收到 IPS 后对其的使用：如其同意文本所述，用于朝圣期间的治疗及任何后续照护。

    某个 Consent 是哪一项同意，以及向朝觐者展示的同意文本，均承载于 Consent.policyRule 中：取自 IPS.HAJJ.CONSENT CodeSystem 的代码，并将 coding.version 设置为该 CodeSystem 的版本。

    东道国 EMR 通过在 ips-pilgrimage 信任域中的信任来识别（参见消息语义中的认证说明）。仅当通行码有效、VHL 未过期、来源方释放同意在其登记系统中处于有效状态、经验证的接收方与 Consent.provision.actor 匹配、目的为治疗且请求处于 Consent.provision.period 范围内时，来源国 HIE 才释放文档。若其中任何一项无法确认，则不允许该请求。

    审计事件

    来源国 HIE 对每个请求都使用记录审计事件 [ITI-20] 记录一条审计事件，无论文档被释放还是被拒绝。VHL 第 1 卷 §1:XX.3 要求 VHL 共享方和 VHL 接收方与 ATNA 安全节点（Secure Node）或安全应用（Secure Application）组合，ITI-YY5 §2:3.YY5.5.6 规定两者都宜（SHOULD）记录文档访问请求、所用认证方法、接收方身份、VHL 文件夹 ID 和授权决定。在本指南中，来源国 HIE 记录的审计事件还应当引用：

    • 适用的策略：朝圣者的各项同意，每项以其 Consent.policyRule 代码和 CodeSystem 版本标识（例如本指南示例中的 CONSENT-XXK 和 CONSENT-XXR，版本 2.1.0）；
    • 为作出决定而从同意登记系统（Consent Registry）读取的每条 Consent 的 id 和 meta.versionId；
    • 接收方，以所用的 VHL 认证选项所识别的身份为准；
    • 使用目的（TREAT）；
    • 所释放的文档（返回的 DocumentReference），或拒绝结果。

    本指南不为朝圣使用单独的数据共享协议，因此审计事件所引用的策略就是这些同意本身。东道国 EMR 作为 ATNA 安全节点或安全应用，也宜对其接收的内容进行审计。

    检索 IPS - 请求

    检索 IPS 请求事件事务由东道国电子病历（EMR）向来源国 HIE 发起。

    触发事件

    • 当东道国 EMR 已从 VHL 文件夹中提取 documentReference 的 bundle，并正在请求检索 JSON 格式的 IPS 时，即启动检索 IPS 请求事务。

      消息语义

      消息语义：请求
    • 检索 IPS 请求的消息语义应当（shall）是获取 IPS json 的 GET 请求。
      • 东道国 EMR 应当（shall）充当文档消费者（Document Consumer），并遵循ITI-68。
    消息语义：响应
    • 检索 IPS 请求-响应的消息语义应当（shall）以 Json 文件形式发送 IPS。

      预期操作

    • 接收方 OCHIE 以 IPS Json 作出响应。
